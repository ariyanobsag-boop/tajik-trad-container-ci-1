# TAJIK_TRAD - Public Read-Only Market Data Service

## معرفی

این بسته شامل یک سرویس مستقل و فقط‌خواندنی برای دریافت و نمایش
اطلاعات مرجع بازار طلا است.

این سرویس برای نمایش آموزشی و اطلاعاتی طراحی شده است.
هیچ قابلیت ثبت سفارش، اجرای معامله یا اتصال به حساب کارگزاری ندارد.

## امکانات

- دریافت اطلاعات مرجع لحظه‌ای از منبع عمومی
- دریافت نقاط نمونه‌برداری‌شده اطلاعات درون‌روزی
- نمایش وضعیت سلامت سرویس
- جداسازی کامل از سرور اصلی پروژه
- محدود بودن مسیرهای سرویس به درخواست‌های GET

## مسیرهای API

| مسیر | روش | کاربرد |
|---|---|---|
| `/health` | GET | بررسی سلامت سرویس |
| `/api/v1/feed/spot` | GET | دریافت اطلاعات مرجع Spot |
| `/api/v1/feed/intraday` | GET | دریافت نقاط نمونه‌برداری‌شده درون‌روزی |

نمونه درخواست اطلاعات درون‌روزی:

`/api/v1/feed/intraday?symbol=xau&hours=6`

## نکات مهم درباره داده‌ها

- قیمت‌های دریافتی، اطلاعات مرجع و indicative هستند.
- قیمت مرجع الزاماً قیمت قابل معامله یا تضمین‌شده نیست.
- داده‌ها ممکن است با تأخیر، کش‌شدن، قطعی یا محدودیت منبع مواجه شوند.
- نقاط درون‌روزی با قالب `{t,p}` ارائه می‌شوند و کندل OHLC نیستند.
- از این نقاط نباید کندل OHLC ساختگی تولید شود.
- زمان و وضعیت تازگی داده باید از پاسخ منبع بررسی شود.

## نیازمندی‌ها

- Python 3.13
- FastAPI 0.141.1
- Requests 2.32.4
- Uvicorn 0.54.0

## ساخت بسته با Docker

در پوشه‌ای که Dockerfile قرار دارد اجرا کنید:

`docker build -t tajik-trad-public-feed .`

## اجرای محلی

`docker run --rm -p 8080:8080 -e PORT=8080 tajik-trad-public-feed`

پس از اجرا، مسیر سلامت سرویس:

`http://127.0.0.1:8080/health`

## پورت و بررسی سلامت

- پورت پیش‌فرض سرویس `8080` است.
- اگر پلتفرم میزبانی متغیر محیطی `PORT` را تعیین کند، سرور همان مقدار را استفاده می‌کند.
- مسیر `/health` فقط زنده بودن فرایند وب را بررسی می‌کند؛ سلامت منبع داده یا تازگی اطلاعات را تضمین نمی‌کند.
- Healthcheck کانتینر نیز فقط مسیر محلی `/health` را بررسی می‌کند و درخواست خارجی نمی‌فرستد.

## استقرار روی سرور

برای دسترسی از دستگاه‌های دیگر، سرویس باید روی میزبان قابل دسترس اجرا شود.

الزامات محیط عمومی:

- HTTPS باید توسط زیرساخت استقرار یا پراکسی معکوس فراهم شود.
- محدودسازی نرخ درخواست‌ها باید در پراکسی معکوس یا لبهٔ پلتفرم میزبانی انجام شود. این بسته محدودکنندهٔ نرخ توزیع‌شده درون‌برنامه‌ای ندارد.
- محدودیت CPU، حافظه و تعداد اتصال‌ها در زیرساخت میزبان تنظیم شود.
- سرویس در حال حاضر کش درون‌حافظه‌ای و مخصوص هر فرایند دارد. اجرای چند worker یا replica باعث ایجاد کش‌های مستقل و احتمال افزایش درخواست‌های منبع می‌شود. قبل از مقیاس‌پذیری، راهکار کش مشترک یا کنترل بار مناسب لازم است.
- برای برنامهٔ بومی اندروید، CORS لازم نیست. اگر مصرف‌کنندهٔ مرورگری اضافه شد، فقط مبدأهای مشخص و موردنیاز مجاز شوند.
- در صورت سازگاری پلتفرم، اجرای کانتینر با فایل‌سیستم فقط‌خواندنی و محدودیت دسترسی سیستم‌عامل ترجیح داده می‌شود.

تا قبل از تکمیل این الزامات، سرویس نباید به‌عنوان یک سرویس عمومی بدون محافظ منتشر شود.
